# Build pins

The build contract is target-specific and reproducible. For a target, the
effective tuple

```text
(CHROMIUM_VERSION, DEPOT_TOOLS_REVISION, args/<target>.gn,
 linux/Dockerfile when applicable, patches/series)
```

fully determines the output binary. Changing any input changes what ships, so
each input is pinned in the repository rather than treated as a convention.

`CHROMIUM_VERSION` is `152.0.7977.83`, recorded in
[`build/CHROMIUM_VERSION`](CHROMIUM_VERSION). The package and artifact
contracts use this exact version.

## Target definitions

`build/args/<target>.gn` is the complete effective GN configuration for one
release target. It is not a generic host hint: target OS, CPU, SDK/toolchain,
linker, sysroot or container boundary, and reproducibility settings belong in
the target definition. A target must not inherit Linux container assumptions
when it is macOS or Windows.

The initial target and artifact names are:

| Target | Definition | Artifact |
| --- | --- | --- |
| `linux-x64` | `build/args/linux-x64.gn` | `apostate-152.0.7977.83-linux-x64.tar.zst` |
| `linux-arm64` | `build/args/linux-arm64.gn` | `apostate-152.0.7977.83-linux-arm64.tar.zst` |
| `macos-arm64` | `build/args/macos-arm64.gn` | `apostate-152.0.7977.83-macos-arm64.tar.zst` |
| `windows-x64` | `build/args/windows-x64.gn` | `apostate-152.0.7977.83-windows-x64.zip` |

Linux targets use the pinned `build/linux/Dockerfile` boundary where the build
workflow requires it. macOS runs against the pinned SDK/toolchain settings in
its target definition. Windows requires its own explicit SDK, toolchain,
packaging, and reproducibility settings; it is not a Linux-container variant.

At the current release-candidate baseline, the macOS arm64 and Linux x64
definitions are present. Linux arm64 and Windows x64 definitions, and the
corresponding runner evidence, are still required before claiming four-target
build readiness.

## Resolved manifest

`MANIFEST.lock` is generated by `scripts/build.sh` and records what a build
actually resolved, including the target, Chromium revision, patch-series and
GN-argument hashes, toolchain or image information, and output hashes. An
independent rebuild from the same pins must reproduce the release output hashes
before an artifact is publishable. The checked-in file is evidence of its
recorded target only; it is not evidence for targets that were not built.

See [`docs/RELEASE.md`](../docs/RELEASE.md) for artifact names, manifest
fields, signature verification, and the release-candidate gate.
