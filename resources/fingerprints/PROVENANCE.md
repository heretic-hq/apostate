# Provenance of files in this directory

Under axiom A2 every patch cites the capture it reproduces, so the tier of each
file here is load-bearing. Tiers are defined in `docs/METHODOLOGY.md` §3.

| File | Tier | Usable for |
|---|---|---|
| `02996-apple-m4-max.json` | mixed | Scalar fields only. Render fields are **not** measured. |
| `02996-apple-iphone-15-chrome.json` | **not a capture** | Field layout only |
| `02996-apple-iphone-15-safari.json` | **not a capture** | Field layout only |

## How to tell a capture from a template

Four fields encode measured device output — `canvas`, `webgl`, `audio`,
`rectangles`. Each is a 64-byte digest followed by a block of sampled bytes. The
sample block is what the device actually produced, so its entropy is the test:

| | Genuine capture | Template |
|---|---|---|
| `audio` sample block | dozens of distinct byte values | 1 (constant `0x88`) |
| `rectangles` sample block | varies per device | byte-identical across devices |

`corpus/build_oracle.py` applies this test automatically and refuses to mark a
degenerate row as T0, so a template cannot silently become ground truth.

## The Apple files — produced by a broken collector

All three were generated by `collect_m4_fingerprint.js`, which constructs values
shaped like a bablosoft fingerprint without measuring them. Reading the source:

- **`rectangles` is entirely synthetic.** `sha1("rects:m4max:meas")` and
  `crc32("rectangles")` are constants, and the sample block is
  `Math.sin(i * 1.5) * 50000`. `getClientRects()` is called but only its
  `length` is used. Every device it runs on yields the same value.
- **`audio` is measured then discarded.** The `OfflineAudioContext` render sits
  inside `catch(e){}` that falls back to a zero-filled array. All three files
  share one audio digest, so the render threw. The tail formula
  `floor((s + 1.0) * 40) + 0x60` then maps s≈0 to a constant `0x88`.
- **`webgl` reuses the canvas tail**, not WebGL pixels, and its second digest
  hashes only the vendor and renderer strings.
- **`canvas`** is genuinely measured, but `(p & 0x1F) + 0x75` crushes each pixel
  to five bits, discarding almost all of what was rendered.

`02996-apple-m4-max.json` was recaptured on real headed Chrome 152 and its
**scalar** fields are now trustworthy: user agent, `1728×913` screen, and the
ANGLE Metal M4 Max renderer string are real. Its four render fields still come
from the paths above and remain unusable.

The two iPhone files were not recaptured. Their metadata is also self-contradictory
— both are tagged `["Linux","Safari","Desktop"]` for iPhone profiles, and the
Safari one claims iOS 18.7 with `Version/26.5`, which do not ship together.

## Consequence

A correct collector is a prerequisite for any further capture, and it is the
same tool as the V3 conformance harness. It lives in `capture/`.

It stores raw measurements rather than digests, because the render fields here
are digests plus a lossy tail, and those support *verification* but not
*replay* — pixels cannot be reconstructed from a SHA-1. Replaying canvas, WebGL
and audio needs the actual render output, which is what `capture/` records.
